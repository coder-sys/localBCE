# Provider pre-check contentDigest v1

Contract `RR/PROVIDER-APP/RULE-BUNDLE/v1`. Normative source: Python
`provider_app/provider_app/codec.py` (`bundle_content_digest` 288-294, `_load`
135-153, `bundle_from_mapping` 301-453). Where this page and the code
disagree, the code wins. Synthetic, non-PHI, nonpayment: `proofSuiteId=null`,
`production_usable=false`, `activation=false`. A digest binds local content
bytes only; it proves no issuer authority, truth or approval.

Vectors: `conformance/vectors/provider_digest_v1/` (`cases.json` lists 14
positive and 32 must-reject cases, one file each), generated by
`tools/gen_provider_digest_v1_vectors.py`, checked by
`tests/test_provider_digest_v1_conformance.py`.

## 1. Where a contentDigest appears

| Object | Role |
|---|---|
| RULE-BUNDLE/v1 (`rule-bundle-v1.schema.json`) | Required member `contentDigest`; the only hashed object. |
| CHECK-RESULT/v1 `bundle.contentDigest` | A copy of the verified bundle's digest (`codec.py` 546). Never hashed or recomputed from the result. |
| CHECK-REQUEST/v1 | None. Claim facts never enter the digest. |

## 2. What is hashed

The bundle as parsed JSON, minus the one top-level member named
`contentDigest`. All other 12 members are hashed, including `provenance` and
every rule object. Only the top-level key is dropped (vector `pos-11`);
nested keys of that name stay. The hashed value is the parsed value, never
the input bytes: indentation, key order, `\u` spelling, escapes and CR/LF/tab/
space between tokens do not matter (`pos-02`, `pos-03`).

## 3. Hash and encoding

`digest = "sha256:" + lower-case hex(SHA-256(canonical))`, 71 characters.
`canonical` is the section 4 text encoded as ASCII. No domain tag, prefix
bytes, length or terminator. Example: `{}` gives
`sha256:44136fa355b3678a1146ad16f7e8649e94fb4fc21fe77e8310c060f61caaff8a`.

## 4. Canonical JSON

Python `json.dumps(content, sort_keys=True, separators=(",", ":"),
ensure_ascii=True)`; byte for byte:

- No whitespace anywhere; `,` and `:` only.
- Object keys sorted by Unicode code point (so U+FFFF before U+10000; UTF-16
  order would differ, `pos-10`). Applies at every depth. Arrays keep order.
- Strings in `"`. Escapes: `\"` `\\` `\b` `\f` `\n` `\r` `\t`. Every other
  code point outside U+0020..U+007E (controls, DEL U+007F, all non-ASCII)
  becomes `\u` plus 4 **lower-case** hex digits; `/` is not escaped. Code
  points above U+FFFF become a surrogate pair, e.g. `\ud83d\ude00`. Lone
  surrogates are written as themselves (`\ud800`); input hex case is
  irrelevant (`pos-06`, `pos-07`, `pos-12`).
- No Unicode normalisation: U+00E9 and `e` U+0301 hash differently.
- Integers: decimal, no `+`, no leading zeros, `-` only if negative. Printed in
  full (`pos-09`), up to the interpreter's 4,300-digit limit; longer is
  `JSON_INVALID` (`rej-32`). `-0` parses to `0` and prints `0`. No floats,
  exponents, `NaN` or infinities exist in a loaded document (section 6).
- `true`, `false`, `null`, `{}` and `[]` as written. An accepted bundle
  contains no booleans; the hash function itself prints them.

Accepted bundles hold only the schema's ASCII keys, enum strings, dates,
timestamps and integers (versions 1..65535, source age 0..365, cents
0..100,000,000), so non-ASCII text, escapes and large integers occur only in
the `mapping` vectors, which test the hash function alone.

## 5. Verification

`parse_bundle_bytes` validates every other field first (rule errors win over
a digest error), then:

1. `contentDigest` must be a non-empty string of at most 71 characters and
   match `^sha256:[0-9a-f]{64}$` (`fullmatch`, which already forces exactly 71
   characters, so the length cap never fires on its own; `rej-06`), else `BUNDLE_DIGEST_INVALID`.
   Upper-case hex or prefix, a missing prefix, `null` and a trailing newline
   all land here.
1. Compare as plain strings with `!=` (case-sensitive, not constant time; the
   value is public). Unequal: `BUNDLE_DIGEST_MISMATCH`.

The evaluator recomputes the digest from the re-serialised bundle
(`evaluator.py` 139-143, `codec.bundle_to_mapping`) and adds the issue
`BUNDLE_CONTENT_DIGEST_MISMATCH` if it differs or cannot be computed.
`provider_app/provider_app/checker.py` 239-244 repeats the same test, but
returns `False` with no string.

## 6. Input refusals before the digest

Error text is `InputError.code`. The first three rows run in this order;
rows marked (P) share one parse.

| Code | Cause |
|---|---|
| `JSON_BYTES_REQUIRED` | argument not exactly `bytes` (`str`, `bytearray`) |
| `BUNDLE_TOO_LARGE` | more than 16,384 bytes |
| `JSON_DEPTH_EXCEEDED` | more than 8 nested `{`/`[` (byte scan outside strings, before parsing) |
| `JSON_INVALID` | not UTF-8 (a BOM too), not JSON, recursion, or integer too long for the interpreter |
| `JSON_DUPLICATE_KEY` (P) | repeated key at any depth, compared after unescaping |
| `JSON_FLOAT_UNSUPPORTED` (P) | any number with `.`, `e` or `E`, so `1.0`, `1e2` |
| `JSON_CONSTANT_UNSUPPORTED` (P) | `NaN`, `Infinity`, `-Infinity` |
| `JSON_OBJECT_REQUIRED` | top level not an object |
| `BUNDLE_SCHEMA` / `BUNDLE_RULE_SCHEMA` | key set differs from the schema, extra or missing, including a missing `contentDigest` |
| `BUNDLE_VERSION_INVALID` etc. | field checks, see `codec.py`; `true` is not an integer |

(P) is reported by position, not table order: the parser stops at the first
offending token in the document. A float or constant fires when read, a
duplicate key only when its object closes. So `{"a":1,"a":2,"b":1.5}` gives
`JSON_FLOAT_UNSUPPORTED`, `{"a":NaN,"b":1.5}` gives
`JSON_CONSTANT_UNSUPPORTED` and `{"o":{"k":1,"k":2},"f":1.5}` gives
`JSON_DUPLICATE_KEY` (`rej-29` to `rej-31`). Rule errors beat digest errors
(`rej-28`). `JSON_BYTES_REQUIRED` needs a non-`bytes` argument, which a vector
file cannot express; the product test covers it.

The code canonicalises: whitespace, key order and escape spelling are
accepted and normalised by the hash. It refuses a digest made over any other
form (unsorted keys, spaced separators, the key `contentDigest` included):
`BUNDLE_DIGEST_MISMATCH` (`rej-08` to `rej-11`). Each `rej-*` vector pins one
code. Unicode lone surrogates, NFC and non-ASCII strings are digested but
cannot occur in an accepted bundle.

## Open discrepancies

1. `rule-bundle-v1.schema.json` types numbers `integer`, which in JSON Schema
   2020-12 admits `1.0`; the code refuses every float token.
2. The schema does not state the digest rule, the 71-character cap,
   duplicate-key refusal, unique `ruleId`, or interval and min/max ordering;
   only the code enforces them. The schema's depth bound 8 matches the code.
3. Edge cases depend on the Python `json` module: the integer digit limit
   (`JSON_INVALID`) and acceptance of lone surrogate escapes.
