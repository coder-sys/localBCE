# Continuity segments `RR/GATE/SEGMENT/v1`

Normative source: the code. Writer `app/right_rail_financial_owner.py` (`_digest`, `_canonical`, `_seal_segment`,
`_manifest`, `export_history`, `_replay_segment`); checker `app/right_rail_financial_owner_independent.py`
(`_verify_history_export`, `_parse_json`); prose `ARCHITECTURE.md` "History segments". Where prose and code
differ the code wins ([Open discrepancies](#open-discrepancies)). Vectors: `conformance/vectors/segment_v1/`,
generated by `tools/gen_segment_v1_vectors.py`, checked by `tests/test_segment_v1_conformance.py`.

Synthetic, non-PHI, nonpayment: `proofSuiteId=null`, `production_usable=false`, `activation=false`.

## 1. Scope

Covered: the digests, the seal, the file and manifest layouts, the chain and the bounds. Opaque here: the content of
`events`, `rows`, `identity` and `meta` (rows of the owner's tables; a row is a JSON object of its columns, a BLOB as
`{"hex":"<hex>"}`, no float) and the event id/head hash (`RR/FINANCIAL/EVENT/v2`, `HEAD`; `_verify_event`). The
checker also needs an external trusted authority (id, epoch, digest, actors: `index.json` gives it). A segment-only
implementation can check every rule below except "head of the last event" and the row/meta/identity content.

## 2. Canonical JSON

Exactly Python `json.dumps(v, sort_keys=True, separators=(",", ":"), ensure_ascii=True, allow_nan=False)` as ASCII
(owner `_canonical`, checker `_canonical`). Keys sorted by code point. Strings: `"` and `\` as `\"` `\\`; `\n \r \t
\b \f` as short escapes; any other character outside 0x20..0x7e (other controls, 0x7f, all non-ASCII) as `\u` plus four
lowercase hex digits, a character above U+FFFF as a lowercase surrogate pair (e.g. `\ud83d\ude00`); `/` and every other
printable ASCII character bare, never escaped. Integers in -2^63..2^63-1, shortest decimal, `-0` and leading zeros
never written (`-0` parses as 0 so it is not canonical; a leading zero is a parse refusal); no float (any fraction or
exponent), NaN or Infinity. `true`, `false` and `null` are legal JSON here; fields that need otherwise are refused by
section 5/6 rules. A file or digest input is accepted only if it equals the canonical form of what it parses to.
Duplicate keys, nesting over 32, or over 250,000 values are refused. Hex digests are 128 uppercase hex digits (64
bytes). A BLOB is `{"hex":"<hex>"}`: writers emit uppercase; a reader decodes either case, and digests hash the text as
written. The owner's identifiers are ASCII-only (`_ID`), so it emits no non-ASCII text: the escape vectors are must-reject.

## 3. Digest

`D(label, body) = SHA3-512( "RR/GATE/SEGMENT/v1" 00 || u64be(len(label)) || label || u64be(len(body)) || body )`,
the domain being the 19 bytes `RR/GATE/SEGMENT/v1` plus one `00` byte; lengths are 8-byte big-endian.

- `projection_root = D("rows", canonical(rows))`
- `segment_digest = D("seal", canonical(seal))`
- `manifest_digest = D("manifest", canonical(manifest without manifest_digest))`

## 4. Seal

An object with exactly these keys:

| key | type, range |
|---|---|
| `format` | the string `RR/GATE/SEGMENT/v1` |
| `segment_index` | int, 0..9,999, the file's position |
| `first_sequence` | int >= 1; 1 for segment 0, else the previous `last_sequence` + 1 |
| `last_sequence` | int >= `first_sequence`, <= 10,000 over the whole export |
| `event_count` | int, `last_sequence - first_sequence + 1` = number of `events` |
| `previous_digest` | hex; 128 `0` digits for segment 0, else the previous `segment_digest` |
| `event_head` | hex, the `head` of the segment's last event |
| `projection_root` | hex, section 3 |

## 5. Files

`segment-%08d.json` (decimal index, eight digits), one per index 0..`segment_count`-1; canonical JSON of exactly:
`events` (event rows, ascending `event_sequence`, consecutive from `first_sequence`, at least one), `rows`
(`{"table":T,"row":R}` final images of the projection-table rows the segment touched; sorted ascending by the
canonical bytes of each record; one record per table row key), `seal`, `segment_digest`, `signature`. `signature` is
reserved: it must be `null` in v1 and is in no digest. Size 1..16,777,216 bytes (`MAX_SEGMENT_BYTES`).

`manifest.json`: canonical JSON of exactly `format` (`RR/GATE/SEGMENT/v1`), `identity` (the `financial_identity`
row), `meta` (the `financial_meta` row), `segment_count` (int 0..10,000), `last_segment_digest` (128 `0` digits if
count is 0, else the last `segment_digest`), `manifest_digest`. Size 1..1,048,576 bytes. A reader opens bytes as
Latin-1 and needs them ASCII; any other byte is a refusal.

## 6. Checker rules

In order; a refusal is the string shown (`N` = segment index). All are refusals of the whole export.

1. Manifest file: unreadable `history:manifest:read`; size `:bytes`; non-ASCII `:ascii`; JSON `:parse`, `:float`,
   `:bounds`, `json:duplicate-key`, `:noncanonical` (prefix `history:manifest`).
2. Keys not exactly section 5, or `format` wrong: `history:manifest`.
3. `manifest_digest` wrong: `history:manifest-digest`.
4. `meta`/`identity` rows and trusted authority/scope/schema: `history:meta`, `history:identity*`.
5. `segment_count` not an int in 0..10,000 (the over-bound refusal): `history:segment-count`.
6. For N = 0..count-1, the prefix `history:segment:N` plus `:read`, `:bytes`, `:ascii`, `:parse`, `:float`,
   `:bounds`, `:noncanonical` (section 2; duplicate keys `json:duplicate-key`).
7. Keys not exactly section 5, `signature` not null, or `rows` not a list: `history:segment:N:shape`.
8. `events` is a list of well-formed event rows: `continuity:rows:financial_events` if it is not a list, else
   `continuity:<table>:...`.
9. Events: the first event has `event_sequence` = previous last + 1 and each next one more (`history:sequence`);
   total over 10,000 `history:row-cap`; id/head/predecessor hash `history:event-id`, `:head`, `:predecessor`.
10. Each rows record is `{table, row}` with a projection table (`history:segment:N:record`) and a well-formed row
    (`continuity:<table>:...`).
11. At least one event, `rows` sorted by canonical bytes, no two records of one row key:
    `history:segment:N:records`.
12. The recomputed seal (section 4: index N, first/last/count from the events, `previous_digest` = running digest,
    `event_head` = last head, `projection_root`) must equal `seal`, as canonical bytes: `history:segment:N:seal`.
13. `segment_digest` = D of that seal: `history:segment:N:digest`. The running digest becomes it.
14. After the last segment: `last_segment_digest` = running digest, `meta.sequence`/`meta.history_head` = last
    sequence/head, and `identity.anchor_sequence` <= last sequence: `history:manifest-binding`.

`restore_continuity(history=...)` runs this checker (a refusal is `history_export:<string>`), then replays each
segment and reseals it; the reseal must equal `segment_digest` or `history_replay_mismatch`.

## 7. Writer bounds

A record's size is `len(canonical(record)) + 1`; a row counts once, at its latest size. The open segment is sealed
after the write that leaves it at 4,096 events or 4,194,304 record bytes (soft), and at every export. A write that
leaves more than 10,000 events, or record bytes + 4,096 > 16,777,216, is refused `history_segment_size` and rolls
back; so is a seal whose `rows` + event bytes + 4,096 exceed 16,777,216. The checker enforces only the hard bounds
(5, 6, 9).

## 8. Vectors

`positive/{segment0_only,mid_chain,empty_history}`: an owner export (several segments, one segment, none) with
`expected.json` (digests, heads, sequences). `negative/<name>`: only the files that differ from
`positive/mid_chain`, plus `delete.json` (a list of file names to remove from the copy) when a file is missing; each
breaks one rule, `index.json` names it and the refusal. A vector with several faults is named by the earliest rule of section 6 that
fires. `index.json` also holds the trusted authority. Not covered by
a vector: the 4,096-event soft bound and the 16 MiB file bound (several MB), a manifest over 1 MiB, `history:row-cap`
(over 10,000 valid events), `history:event-id`/`:head`/`:predecessor` (event hashing is out of scope, section 1).

## Open discrepancies

- Prose says the checker recomputes "chain, counts and event heads"; the code also refuses an empty segment,
  unsorted or repeated row records, a non-null `signature` and any non-canonical byte.
- Prose: a write "past 10,000 events or 16 MiB" fails; code: 16 MiB less the 4,096-byte frame, counted in record
  bytes, not file bytes.
- Prose: the soft seal is "4 MiB"; code: 4,194,304 summed record bytes (events, plus one image per touched row).
- Prose omits the manifest size cap (1 MiB) and the 16 MiB file cap.
- Prose says replay "reseals byte-identically"; code compares only the resealed `segment_digest`.
- The JSON layer accepts a lone surrogate (`\ud800`) as canonical (the encoder writes it); no vector.
- A reader accepts lowercase or mixed-case hex in `{"hex":...}`; only uppercase is written; no vector.
- A repeated `segment_index` has no rule of its own; it fails through section 6 rules 9 and 12.
