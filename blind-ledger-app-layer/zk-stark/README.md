# Blind Ledger STARK PoC

Status: working PQ STARK core, soundness-checked, PENDING CRYPTOGRAPHIC AUDIT.

This directory is intentionally separate from the existing Groth16 `../zk/` directory. It does not replace, modify, or wire into the existing app layer.

## What It Builds

- STARK system: Winterfell `0.13.1`.
- Proof type: transparent hash-based STARK; no trusted setup.
- Adjudication logic: G1-G10 normalized claim gates.
- Public outputs: claim commitment, decision, failure code.
- Private witness: normalized gate inputs plus comparison and inverse witnesses.

## Commands

Run tests:

```powershell
cargo +1.96.0-x86_64-pc-windows-msvc test
```

Generate proofs and report:

```powershell
cargo +1.96.0-x86_64-pc-windows-msvc run --release -- outputs
```

Verify a serialized proof artifact:

```powershell
cargo +1.96.0-x86_64-pc-windows-msvc run --release --bin verify_artifact -- outputs/proofs/approved.stark outputs/public/approved.json
```

## Output Files

- `outputs/stark_run_report.json`: proof sizes, timings, verified flags, tamper result.
- `outputs/proofs/*.stark`: serialized Winterfell proof bytes.
- `outputs/public/*.json`: public inputs for each proof.
- `stark_vs_groth16.md`: migration tradeoff table.
- `verifier/WINTERFELL_VERIFIER_PATH.md`: verifier status and on-chain gap.

## Honest Caveats

- The Rust/off-chain verifier works; Solidity/on-chain STARK verifier is not generated by Winterfell in this run.
- The claim commitment is an AIR-bound algebraic PoC commitment, not a production-audited hash commitment.
- Static/tests check the math and binding behavior, not Medi-Cal legal correctness.
- Human cryptographic audit is required before production trust.
