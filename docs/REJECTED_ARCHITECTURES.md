# Rejected architectures

Owner: current architecture prohibitions. Status: active rejection record; it contains no
retired implementation, benchmark, source map, phase history, or revival procedure.

- BL-PQ512, H4, K128, and K512 proof layouts, monolithic STARK-era launch blockers, and
  version-3-composite assumptions are rejected historical directions. They are not current global
  gates; any activated capability/profile must instead close its exact theorem, semantic,
  independent-verifier, PQ, privacy, resource, recovery, and ownership gates.
- L2, rollup, sequencer, bridge, or Ethereum settlement reconstruction is rejected because official state payment rails move funds and Ethereum is only a later governed L1 checkpoint.
- Cairo/Starknet/Solidity settlement code is rejected because no smart-contract settlement layer is part of the current design.
- Caller-selected plaintext evaluation or a private-proof-to-plaintext downgrade is rejected because the verifier-owned automatic control set fixes evidence mode and fail-closed admission forbids fallback.
- Fixed-shape/AIR compatibility as a production authority is rejected because current Native-v3 semantics, exact SHA3-512 identities, and independent verification own the active boundary.
